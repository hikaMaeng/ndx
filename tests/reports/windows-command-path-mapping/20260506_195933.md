# Windows Command Path Mapping - 2026-05-06 19:59:33

## Change Under Test

- Docker-backed external tools should rewrite embedded Windows host workspace
  paths in string arguments before execution.
- The host project `F:\dev\test2` and sandbox mount `/workspace` should be
  equivalent for tool commands, not only for structured `cwd` and `dir_path`
  fields.

## Expected Result

- `F:\dev\test2`, `F:/dev/test2/apps`, and
  `F:\dev\test2\tests\reports` become `/workspace`,
  `/workspace/apps`, and `/workspace/tests/reports` when sent into sandboxed
  tool runtimes.
- Shell commands no longer create drive-letter folders such as `F:` or `F0`
  inside the project workspace.

## Conclusion

execution. It does not depend on model prompt compliance.
